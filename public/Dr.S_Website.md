### 0.16.2 Automatic language selection — privacy/performance-first
When a visitor enters the site, select the initial language using the following priority order:

1. **Explicit visitor choice** saved previously (language switcher preference/local storage or an equivalent first-party preference) always wins.
2. **Browser/device language** (`navigator.languages` / `navigator.language`) is the primary automatic signal. If Arabic is one of the preferred languages (for example `ar`, `ar-SA`, `ar-AE`, `ar-LB`, `ar-JO`, `ar-EG`, etc.), prefer Arabic; otherwise prefer English.
3. **Coarse visitor-country/location signal** may be used as a secondary fallback only when a reliable first-party/edge/hosting signal is genuinely available. If the visitor is detected as being in an Arabic-speaking country and the browser language does not give a clear preference, prefer Arabic. Do not add a heavy third-party IP-geolocation service merely for language selection.
4. If no reliable signal exists, default to **Arabic** because Arabic is the primary brand language.

Do not use invasive fingerprinting, unnecessary analytics, or hidden profiling to determine language. Do not collect or persist precise location merely to choose a language.

### 0.16.3 Do not break SEO with forced redirects
Automatic language selection must **never prevent search engines from crawling or indexing both language versions**.

Do not implement unconditional server/client redirects that make `/ar/` or `/en/` inaccessible based solely on the visitor's country or browser language. Language preference should behave as a lightweight UX convenience, not as an indexing barrier.

Respect direct URL intent: if a visitor explicitly opens `/ar/...`, keep them on Arabic; if they explicitly open `/en/...`, keep them on English. A previously saved preference must not override an explicit locale URL.

For the homepage/root path, a lightweight first-visit language selection may route the visitor to the preferred localized homepage when technically appropriate, but the localized URLs must remain directly accessible, crawlable, shareable, and canonicalized independently. Avoid redirect loops and avoid layout/content flashes during language initialization.
